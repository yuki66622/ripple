# 评测 Harness v1 验收 · 2026-09-26

范围：本地 Binance 2025 年 1 月、BTC/ETH/SOL、Kronos 数字预测、固定金融指标、滚动回放与模型比较。不是完整云服务或自动实时调度的验收。

结论：本轮评测 harness 的工程验收通过；原版模型在固定 96 窗口实验中未超过简单基线。两者分别报告。用户要求先完成 harness，再做 LoRA；本轮没有训练。

| 验收项 | 实际证据 |
|---|---|
| 输入与真值隔离、样本预测前冻结 | 96 个时间均匀选择的输入窗口；每资产 256 根已知数据，未来 30 根仅用于独立评分 |
| 真实模型执行与完整分母 | 96/96 scored，0 失败、0 未运行、0 自动重试；原始输出和每个任务产物保留 |
| 基线比较 | 同窗口、同资产、同真值比较收益和波动率；三资产等权和固定日历分段；原报警规则单独评分 |
| 算术独立验证 | 标准库从原始 close 和真实行情复算，96 窗口的 1,152 条主要指标行一致；24 个汇总标量与正式比较器一致 |
| 损坏证据拒绝 | 修改预测价格、审计记录、基线分数、连贯修改的真值评分或损坏对象形状，都不能形成完整成功报告；保留失败分母 |
| 公平模型对照 | 输入、来源、预测配置、采样、tokenizer、adapter、校验政策、运行后端、库版本和时间语义必须一致；允许模型权重和标签不同 |
| 对照负例 | 采样/配置/目标不一致、独有窗口、全部失败、零分母等测试通过；不会将 naive 误差误用为另一模型的误差 |
| 真实自对照 | 同一真实 8 窗口批次分别作为左右输入，全 8 窗配对，两指标×四汇总口径均为零差异、8 次平局；明确 self_comparison，不冒充微调结果 |
| 项目回归 | 154 项检查通过；覆盖应用、分发、模型输出校验、数据、金融算术和新比较器 |

首次完整检查中的本机 HTTP 端口测试被沙箱权限阻断；在允许本机端口的环境完整重跑，154 项全部通过，耗时 5.224 秒。日志中的小型数值对照是明确标记的测试 fixture，不是模型效果证据。

两个模型已经分别产生批次结果后：

```sh
scenario-lab/.venv/bin/python -m evaluation.model_comparison \
  --left-manifest <原版任务清单> --left-batch-dir <原版批次目录> \
  --right-manifest <对照任务清单> --right-batch-dir <对照批次目录> \
  --out <新的结果文件.json>
```

CLI 会独立核验两份原始批次、重新读取本地真值评分，然后比较各自模型误差。正 skill 表示右侧误差更低；`status=complete` 只表示全部窗口配对完成。对缺失、失败或不兼容项保留左右完整台账，不以交集冒充完整实验。

## 后续实验边界

- 尚无微调权重或真实原版/微调对照结果；当前 8 窗自对照仅证明比较器不会凭空制造改进。
- 当前强证据核验仅支持本地 binance_jan2025；新月份需提供同样可验证的数据适配与冻结清单。
- 1 月数据已经用于探索，不能再称从未观察的最终测试集。开始训练前需要明确训练、验证和独立测试数据边界。
- 本次 96 窗为每资产一条预测路径、一个固定种子；没有证明多路径配置、未来市场表现或跨设备逐位一致。
- 第二台电脑最新检查失败于主机名解析；没有双机结果。没有云部署、自动刷新或 LoRA 训练。
